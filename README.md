# MaxWave — YouTube Music для Яндекс Станции Макс

Экспериментальный мост между штатной Алисой и **YouTube Music ReVanced Extended** на рутированной Станции Макс. Алиса продолжает распознавать речь, а музыкальные запросы и управление проигрыванием направляются в YouTube Music. Звук воспроизводится **самой станцией**.

**Проверено на YNDX‑00053, Android 9, прошивка `5000000921`, с постоянным root через `mysudo` и доступным ADB.** Установка этой прошивки и получение root — предварительные условия. MaxWave **не прошивает Android, не получает root и не делает downgrade**.

> **Все действия — на свой страх и риск. Вмешательство в прошивку и root следует считать необратимым: гарантированного возврата в заводское состояние нет.** Поломка станции, потеря настроек, нарушение работы обновлений и сетевых функций остаются ответственностью пользователя. Есть экспериментальный файл возврата к обычной музыке, но он **плохо протестирован** и не отменяет ранее сделанные изменения прошивки, root или защиты от OTA.

**Важно:** мост выполняется на Windows/macOS/Linux-компьютере. Компьютер и станция должны быть в одной доступной сети, компьютер должен оставаться включённым и не уходить в сон. Это пока не автономная установка всей логики на станцию. В фоне работает процесс MaxWave; системная служба автозапуска не создаётся.

## Быстрый старт — без поиска APK и ручной распаковки

Скачайте **один стартовый файл** из [последнего релиза](https://github.com/ARTEMfisher/maxwave/releases/latest):

| Компьютер | Файл | Запуск |
|---|---|---|
| Windows x64 / Windows 11 ARM64 | `MaxWave-Windows.cmd` | Запустите файл |
| macOS Apple Silicon / Intel | `MaxWave-macOS.command` | В Терминале: `bash ~/Downloads/MaxWave-macOS.command` |
| Linux x64 / ARM64 | `MaxWave-Linux.sh` | `sh ~/Downloads/MaxWave-Linux.sh` |

При первом запуске стартовый файл **сам загрузит, проверит SHA256 и распакует** готовый пакет в `~/MaxWave` (Windows: `%USERPROFILE%\MaxWave`). При необходимости автоматически загрузит отдельный переносимый Python; системный Python не заменяется. APK уже находятся в готовом пакете, пользователю их искать или собирать не требуется. ADB и scrcpy скачиваются и распаковываются для выбранной платформы. При повторном запуске стартового файла открывается главное меню без повторной загрузки полного пакета.

На macOS старт из Терминала позволяет не менять executable-bit скачанного `.command`. Файл не подписан Apple; автоматического обхода защиты ОС нет. На Linux для первого запуска нужны обычные `curl` или `wget` и `tar`. Для Linux ARM64 официального готового scrcpy из этого релиза нет: нужны системные `adb` и `scrcpy` (например, `sudo apt install adb scrcpy`).

Также есть [полный ZIP-пакет релиза](https://github.com/ARTEMfisher/maxwave/releases/latest), если Python уже установлен. Если используете Git clone вместо готового ZIP, первый скрипт сам скачает пакет APK из релиза.

### 1. Приложения и экран — `01_install.py`

Установщик предложит:

1. Выбрать платформу компьютера; правильная уже отмечена по умолчанию.
2. Ввести **IPv4 именно станции**, например `192.168.1.50`. Адрес роутера вместо станции не подходит. Порт ADB по умолчанию — `5555`.
3. Загрузить и автоматически распаковать ADB/scrcpy для выбранной платформы.
4. Проверить комплектные APK и установить Happ, GmsCore, YouTube Music ReVanced Extended и ReVanced Manager.
5. Выбрать приложение в числовом меню — оно откроется на станции, а scrcpy покажет её экран.

Настраивать приложения можно **через scrcpy или обычным пультом Яндекса от станции**.

В Happ добавьте **свою** VPN-подписку, подтвердите штатное разрешение Android на VPN и включите подключение. В GmsCore/YouTube Music войдите в свой Google-аккаунт. Убедитесь, что музыка воспроизводится вручную. Менеджер нужен для дальнейшего управления ReVanced; первоначальный поиск и патчинг APK он выполнять не обязан — подготовленный APK уже в пакете.

Для работы ADB домашняя сеть должна оставаться доступной при включённом VPN. Сначала убедитесь, что VPN работает и компьютер продолжает видеть станцию. Проверки есть в шаге 3; скрипты не меняют DNS, роутер или правила сетевой маршрутизации.

При конфликте подписи/версии уже установленного APK установщик выдаст ошибку. **Автоматического удаления приложений с аккаунтами, подписками и данными нет.**

В меню первого файла выберите **9 — перейти к настройке команд**: откроется следующий шаг.

### 2. Команды Алисы — `02_station.py`

Пункт **1** проверяет устройство, сборку, root, версию YouTube Music и подготавливает каталог `/data/local/tmp/maxwave`:

- Frida ARM64 фиксированной версии;
- окружение Android runtime, взятое с этой станции;
- сетевой диагностический probe;
- скрипты запуска и остановки только собственного сервера MaxWave.

Разделы `boot`, `system`, `vendor`, `odm`, `recovery`, `misc` этим шагом **не прошиваются**. Сервер слушает `127.0.0.1:27043` на станции; компьютер подключается через ADB forward. Глобальный SELinux не переводится в Permissive.

Пункт **2** запускает мост в фоне. Пункт **3** останавливает его. Пункт **4** возвращает меню приложений. Пункт **5 — перейти к диагностике** открывает третий файл, пока мост продолжает работать.

Из первого файла подготовка и фоновый запуск выполняются последовательно. Если ADB или процесс Алисы перезапустятся, MaxWave попробует переподключиться. После обновления прошивки или приложений проверяйте совместимость заново: внутренние классы SDK и ReVanced могут измениться.

### 3. Диагностика — `03_diagnostics.py`

Выбирайте тест цифрой:

1. ADB, модель/прошивка, root, SELinux.
2. Версии установленных приложений.
3. Наличие VPN-сети Android и включение UID YouTube Music в опубликованный диапазон VPN.
4. Реальные HTTPS-запросы **от UID музыкального приложения**: доступ к Google/YouTube Music и внешний IP.
5. Текущий трек, состояние MediaSession и рейтинг.
6. Открытие scrcpy.
7. Памятка голосовых проверок.
8. Последние строки локального журнала.

Сетевые проверки не отключают VPN, не снимают блокировки, не подменяют DNS и не включают обновления. Наличие `tun0` само по себе не доказывает работоспособность VPN. Проверка UID даёт более полезный результат, но задержку и доступность каждого сервера подписки по-прежнему проверяйте в Happ. Для диагностики плеера используются только чтение метаданных и отдельный read-only агент; рабочие обработчики не заменяются.

### 4. Возврат к музыке Яндекса — `04_restore.py`

**Экспериментально, плохо протестировано.** Сначала можно посмотреть план без изменений:

```sh
python 04_restore.py --dry-run
```

Обычный режим просит выбрать действие, останавливает MaxWave и только его Frida-сервер, закрывает ReVanced и открывает штатный интерфейс станции. Отдельный пункт может удалить приложения **с их данными**, но лишь те, которых не было до установки MaxWave согласно локальному снимку. Ранее установленные приложения сохраняются.

Это не откат Android, не снятие root и не восстановление заводских разделов. VPN, прежние блокировки OTA, патчи SELinux и другие изменения, сделанные вне MaxWave, автоматически не восстанавливаются. Данные установленного ранее приложения, обновлённого MaxWave, не возвращаются к старой версии.

## Что умеет

### Поиск музыки

- `Алиса, включи Rammstein` — музыка исполнителя.
- `Алиса, включи Du Hast группы Rammstein` — трек с исполнителем.
- `Алиса, включи Кишлак Эй` — сочетание имён без слова «песня».
- `Алиса, включи альбом Mutter группы Rammstein` — очередь альбома.
- `Алиса, включи плейлист …` — поиск плейлиста.
- `Алиса, включи альбом … с канала …` — поиск загрузки конкретного YouTube-канала; для полного альбома отсекаются короткие видео.

Каталог — YouTube Music; для загрузок каналов используется также поиск обычного YouTube. Медиафайлы на компьютер не скачиваются. Поиск не всегда однозначен: слово «альбом», «песня» и имя исполнителя помогают выбрать нужную сущность. Доступность ролика в YouTube не гарантирует возможность его воспроизведения именно в YouTube Music.

### Управление

| Действие | Примеры после «Алиса» |
|---|---|
| Пауза | `пауза`, `стоп`, `хватит`, `останови музыку`, `поставь на паузу` |
| Продолжение | `продолжи`, `играй`, `возобнови`, `сними с паузы` |
| Следующий | `далее`, `дальше`, `следующий трек`, `следующая песня`, `пропусти трек` |
| Предыдущий | `назад`, `предыдущий трек`, `предыдущая песня` |
| Вперёд | `перемотай вперёд на 30 секунд` |
| Назад во времени | `перемотай назад на минуту`, `отмотай на полминуты` |
| Точная позиция | `перемотай на отметку 1:30` |
| Начало | `начни песню сначала` |
| Видео/аудио | `включи видео`, `включи аудио` |
| Информация | `что играет`, `кто поёт` |
| Оценки | `поставь лайк`, `мне не нравится`, `поставь дизлайк`, `сними лайк` |

Команды управляют MediaSession **именно ReVanced**, а не общим медиапультом Android. Аудио/видео переключаются штатным контролом приложения для текущего трека. Лайк и дизлайк меняют настоящие оценки Google-аккаунта; это не безвредные тестовые кнопки.

### Моя волна и настроения

- `включи мою волну` / `мой супермикс` — персональный **My Supermix** аккаунта, авторизованного на станции.
- `включи энергичную музыку` — Energize.
- `включи грустную музыку` — Sad.
- `включи спокойную музыку` — Chill.
- `включи музыку для сна`, `для тренировки`, `для работы`, `для вечеринки`.
- `включи весёлую музыку`, `романтичную музыку`.

Потоки по настроению — публичные тематические подборки YouTube Music. Они не являются персональной «моей волной» с фильтром настроения.

## Что не работает или ограничено

- **Быстрое «далее» без обращения к Алисе не поддерживается:** этого слова нет в штатной акустической модели. `Алиса, далее` работает через обычное распознавание.
- **Быстрое «следующий» без обращения распознаётся ненадёжно.** В испытаниях события `дальше`, `назад`, `стоп`, `играй` приходили; для надёжности используйте `Алиса, следующий трек`. Добавление синонима в JavaScript не обучает акустическую модель новым словам.
- Быстрые команды зависят от прошивки и включения музыкальных быстрых команд в «Доме с Алисой». Громкость и системные действия остаются штатными.
- **Озвучка «что играет» топорная**, особенно с английскими названиями и оформлением заголовков видео. На macOS используется Milena, на Windows — установленный SAPI-голос, на Linux — `espeak-ng`/`espeak` (при отсутствии нужно установить пакет). Windows/Linux-озвучка на реальном устройстве пока не проверялась. Музыка кратко ставится на паузу, затем продолжается.
- Режим повтора, перемешивание, глубокая настройка рекомендаций и полноценный разговорный музыкальный поиск не заявлены как готовые функции.
- Имена нестандартных сценариев умного дома после «включи» могут совпасть с музыкальным запросом. Фильтр бытовых команд не гарантирует понимание любых собственных имён.
- После завершения процесса на компьютере голосовой мост отключается. Уже запущенное воспроизведение может продолжиться.
- Нужен рабочий интернет на компьютере **и** станции; VPN станции не предоставляет VPN компьютеру. Из региона с блокировкой YouTube поиск с компьютера тоже должен иметь доступ к сервису.

## Комплект и платформы

| Компонент | Версия |
|---|---|
| Happ | 4.9.0 |
| YouTube Music ReVanced Extended | 8.12.54, ARM64, пакет `app.rvx.android.apps.youtube.music` |
| ReVanced Manager | 2.6.0 |
| ReVanced GmsCore | 0.3.13.2.250932 |
| scrcpy | 5.0.1, программный VP8 для Amlogic |
| Android platform-tools | 37.0.1 |
| Frida client/server | 17.24.3 |

Готовый APK YouTube Music собран с RVX CLI 5.0.2 и patches 5.14.1: GmsCore support, Remove background playback restrictions, Settings for YouTube Music, Video playback, Enable landscape mode, Hide ads. Личные ключи подписи и данные аккаунта не входят в пакет.

Живые проверки выполнялись на **YNDX‑00053 / 0921 с macOS ARM64**. Для Windows x64/ARM64, macOS Intel и Linux предусмотрены выбор платформы, загрузка нужных инструментов и совместимый код, но **полного испытания на каждой комбинации ОС и железа не было**. Linux ARM64 использует системные adb/scrcpy. Наличие `yandexstation_2` в свойствах не доказывает номер корпуса 00053: проверьте этикетку. Совместимость с 00052, другими сборками, другими Станциями и Android TV не заявляется.

## Для разработчиков

```sh
python -m unittest discover -s tests -v
node bridge/test-core.js
```

Тесты проверяют маршрутизацию, исключение бытовых команд, финальный ASR, повторные события, формулировки времени, платформенные пути, безопасную распаковку, профиль и защиту отката. CI не заменяет физическое тестирование колонки.

Сборка релиза: `python scripts/build_release.py`. Сначала создаётся ZIP с APK и обновляется его хеш, затем полный пакет и стартовые файлы. Публикация не включена в скрипт сборки. Контрольные суммы ресурсов находятся в `resources.json`, приложений — в `apps-manifest.json`. Подробности: [архитектура](docs/ARCHITECTURE.md), [проверки и ограничения](docs/TESTING.md), [сторонние компоненты](THIRD_PARTY.md).

Личные настройки, IP станции, журналы, переносимый runtime и инструменты находятся локально и исключены из Git. VPN-подписки и Google-аккаунты не поставляются. Не выкладывайте `.station`, журналы или APK signing keystore в issue. ADB не следует публиковать в Интернет.
