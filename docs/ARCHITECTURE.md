# Архитектура автономной версии

Компьютер выполняет установку и диагностику через ADB. Он не обрабатывает голос, не ищет музыку, не синтезирует объявления и не поддерживает соединение для работы музыкальных команд. После установки ADB можно отключить.

На станции работают три части: Go-контроллер `maxwaved`, локальный агент внутри `com.yandex.io.sdk` и агент переключателя аудио/видео внутри YouTube Music. Агентов загружают два дочерних процесса `frida-inject`. Отдельный Frida-server и ADB-forward не используются. Контроллер отслеживает завершение дочерних процессов и повторяет подключение; shell-watchdog восстанавливает завершившийся контроллер. После отключения музыки через меню маркер автозапуска удаляется, поэтому перезагрузка не включает отключённый сервис.

В существующий `/data/local/tmp/myscript-max.sh` добавляется только помеченный блок вызова стартового скрипта. Исходный файл копируется до добавления блока. Неизвестный механизм постоянного root установщик не изменяет. Прежние команды root, фильтрации OTA и ADB не заменяются. На устройстве используется блокировка `flock`, а перед завершением процесса проверяется принадлежность исполняемого файла установленному каталогу.

Агенты связываются с контроллером через `127.0.0.1:27044`, newline-JSON и случайный 256-битный ключ. Ключ создаётся отдельно для установки и хранится с правами 0600. Канал не доступен из LAN. Потеря связи переводит музыкальный агент в наблюдение и возвращает штатную обработку Алисы; сетевые запросы не выполняются в её основном потоке. Размер кадра и журнала ограничен.

Речь распознаёт штатная Алиса. Фильтр принимает лишь финальный результат с согласованными request UUID, состоянием и текстом. Промежуточное распознавание не запускает музыку. Музыкальные быстрые команды обрабатываются отдельно; команды активации, громкости и остальные системные действия сохраняют штатный путь. Локальная модель не переобучается.

Каталог запрашивается непосредственно со станции по HTTPS. Сетевой дочерний процесс запускается от UID YouTube Music, чтобы к нему применялась та же политика Android VPN. Ответы ограничены по времени и размеру. Нет отключения TLS-проверок, обхода сертификатов и получения потоковых URL. Для воспроизведения открывается deeplink в ReVanced; для альбома или подборки сохраняется playlist ID. Запросы сменяются по идентификатору: новый запрос отменяет прежний поиск, а агент дополнительно отсекает просроченный результат.

Пауза, продолжение, очередь, перемотка и оценки используют MediaSession только пакета YouTube Music. Аудио/видео переключается штатной кнопкой текущей композиции. Для объявления названия локальный eSpeak NG создаёт WAV на станции; файл передаётся в приватный cache SDK, воспроизводится MediaPlayer и удаляется. Это пока механическое озвучивание, не голос Алисы.

Happ использует штатный Android VpnService. При настройке доступен Android Always-on без lockdown; другой выбранный Always-on не заменяется. VPN должен включать только UID YouTube Music; установщик проверяет реальную политику Android и отклоняет общий туннель или lockdown. Алиса и системные службы идут напрямую. Подписки и Google-сессия остаются в приложениях станции. Проект не извлекает их и не включает в пакет.

Откат выключает сервис и его маркер автозапуска. Это не транзакционный откат Android: первоначальные APK и данные, root и защита OTA не восстанавливаются. Совместимость внутренних классов ограничена указанными в README версиями.
