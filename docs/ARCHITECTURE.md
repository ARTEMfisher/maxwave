# Как устроен MaxWave

`main.py` — главное меню стартовых файлов. `01_install.py` и остальные numbered entrypoints используют только стандартную библиотеку до установки изолированных зависимостей. Профиль и журнал живут в `.station`, зависимости — в `.venv`, инструменты — в `tools/<platform>`. Эти каталоги не попадают в Git или релизные ZIP.

`01_install.py → 02_station.py → 03_diagnostics.py` связаны пунктами меню. Данные IP валидируются как IPv4 с необязательным портом. Android shell-команды собираются через POSIX-quoting независимо от ОС компьютера. Загрузка по HTTPS с фиксированной SHA256, ZIP/TAR распаковываются без внешних команд и с проверкой путей/ссылок. Стартовый bootstrap до Python использует штатный tar/PowerShell для уже проверенных по SHA256 архивов.

Станция заранее должна иметь совместимую прошивку и root. Подготовка пишет только в собственный `/data/local/tmp/maxwave`, сохраняет runtime environment конкретной станции и не меняет загрузчик, разделы, системные APK, правила сети или SELinux Enforcing. Каталог имеет owner-marker; чужая установка не перезаписывается. Frida server слушает только loopback:27043; наружу он не выставляется. Проект не создаёт системный автозапуск.

На компьютере supervisor удерживает настоящий OS-lock (fcntl/msvcrt), запускает worker и восстанавливает подключение. Остановка через файл-запрос кооперативная; PID-файл не используется как основание убить произвольный процесс. Один профиль поддерживает одну станцию. Новые команды отменяют устаревший поиск. Стартовый скрипт Frida не останавливает чужие серверы и проверяет `/proc/PID/exe` перед остановкой своего.

`bridge/agent.js` получает готовые финальные фразы через `JniAliceCapabilityCallback.onAliceState`; микрофон не захватывается. Проверяются состояние, request UUID, финальность, начало распознавания и совпадение текста. Промежуточные результаты музыку не запускают. Идентификаторы хранятся в ограниченном кеше. Быстрые команды подключены отдельным `onPhraseSpotted`. Действия музыкальных быстрых команд обрабатываются один раз, активация/громкость/системные команды продолжают штатный путь.

MediaSession выбирается по пакету `app.rvx.android.apps.youtube.music`. Запросы каталога выполняются на компьютере через ytmusicapi/yt-dlp, затем станция получает deeplink на трек и контекст альбома/плейлиста. Персональный Supermix открывается на самой станции, поэтому используются её Google-сессия и рекомендации; токены аккаунта не извлекаются. Настроения — публичные категории каталога.

Отдельный player-agent переключает штатный AudioVideoSwitcherToggleView текущей композиции. При необходимости существующая Activity выводится на экран. Переключатель не заменяется поиском другого ролика. Объявления создаются локальным системным TTS и временно передаются в приватный cache процесса станции; после окончания временный файл удаляется, а прежнее воспроизведение возобновляется. Оценки используют Android Rating/MediaSession; они меняют реальный аккаунт.

Крупный Java bridge передаётся Frida частями по 6000 символов: в живой сети целый большой скрипт вызывал обрыв транспорта. Версии pinned и приватные имена классов намеренно ограничивают совместимость; слепого «поддерживается любой Android» нет.

Установка добавляет GmsCore в Doze whitelist, предварительно запоминая наличие записи. Откат снимает лишь добавленную этим проектом запись. Для APK сохраняется только признак их существования до установки, не резервная копия данных или старых APK. Откат не является полным транзакционным восстановлением системы.
