# Необязательное управление MaxWave по SSH

## Назначение и границы

Этот модуль предназначен только для станции, на которой SSH-сервер и ключевая аутентификация **уже настроены отдельно**. MaxWave не устанавливает, не запускает и не конфигурирует SSH-сервер. Получение root, Dropbear/rootd, init, SELinux, firewall, OTA и разделы Android остаются вне ответственности модуля.

SSH используется для удалённого управления существующим сервисом MaxWave. ADB по-прежнему нужен для установки и обновления компонентов, установки APK, передачи файлов и scrcpy. SSH не заменяет ADB во всём установщике.

## Требования

- OpenSSH Client на компьютере (команда `ssh` доступна в `PATH` либо задана в локальной конфигурации tools).
- Уже работающий SSH-сервер на станции.
- Ключевой доступ к удалённому пользователю с UID 0 (обычно `root`).
- Проверенный host key станции в пользовательском `known_hosts`.
- Приватный ключ OpenSSH или локальный ssh-agent.

В меню управления станцией выберите пункт 6. В SSH-меню укажите host, port, username и путь к приватному ключу. Для использования локального ssh-agent оставьте путь пустым. Сохранение параметров происходит только после успешного подключения и проверки `id -u == 0`.

## Проверка host key

Клиент всегда использует `StrictHostKeyChecking=yes`. Он не принимает неизвестный host key автоматически и не отключает проверку при ошибке.

Для станции на нестандартном порту OpenSSH обычно записывает имя узла в форме `[HOST]:PORT`. Полученный через `ssh-keyscan` ключ сам по себе не является доверенным: сравните fingerprint с fingerprint, полученным по независимому доверенному каналу (например, из локальной консоли станции или от администратора), и только после совпадения добавляйте запись в `known_hosts`.

Пример для Windows PowerShell (замените адрес и порт своими):

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
ssh-keyscan -p 2222 192.168.50.146 | Out-File -Encoding ascii "$env:TEMP\station-hostkey"
ssh-keygen -lf "$env:TEMP\station-hostkey"
# Сначала сравните fingerprint с достоверным значением!
Get-Content "$env:TEMP\station-hostkey" | Add-Content -Encoding ascii "$env:USERPROFILE\.ssh\known_hosts"
```

Не добавляйте ключ, если fingerprint не удалось независимо проверить. При смене ключа сначала выясните причину; не удаляйте старую запись автоматически.

## Политика клиента

- `BatchMode=yes`, только `publickey` authentication.
- `PasswordAuthentication=no` и `KbdInteractiveAuthentication=no`.
- `StrictHostKeyChecking=yes`.
- `ForwardAgent=no` и `ClearAllForwardings=yes`.
- SSH-команды отправляются через stdin в `/system/bin/sh -s`; пользовательский ввод не конкатенируется в удалённые shell-команды.
- В локальном `.station/config.json` сохраняются адрес, порт, имя пользователя и путь к ключу. Содержимое ключа не читается, не копируется и не включается в пакет или Git.
- Параметры можно удалить из меню; это не затрагивает SSH-сервер, ключи или `known_hosts`.

## Действия SSH-меню

1. Настроить и проверить SSH-подключение.
2. Повторно проверить соединение и UID 0.
3. Показать маркер MaxWave, флаги включения, boot hook, daemon и watchdog.
4. Проверить наличие и синтаксис управляющих скриптов, исполняемость контроллера, длину IPC token и наличие boot hook. Значение token не выводится.
5. Сохранить локальную копию `/data/local/tmp/myscript-max.sh` в `.station/ssh-backups`. На POSIX-клиентах каталог и backup-файл получают режимы 0700/0600. На Windows действуют ACL родительского профиля пользователя; храните профиль под защитой своей учётной записи. Boot script может содержать чувствительные настройки; не публикуйте копию и не включайте её в Git.
6. Запустить существующий `/data/local/tmp/maxwave-native/start.sh`.
7. Остановить существующий `/data/local/tmp/maxwave-native/stop.sh` (требуется явное подтверждение).
8. Перезапустить сервис через штатные stop/start scripts с ожиданием завершения watchdog.
9. Показать последние 50 строк текущего и предыдущего `daemon.log`.
10. Удалить только сохранённые на компьютере параметры SSH.

Перед запуском, остановкой, чтением статуса, проверкой конфигурации или резервным копированием проверяется marker `maxwave-station-native-v1`. Если каталог не принадлежит MaxWave, команда не выполняется. Статус, проверка и backup не изменяют конфигурацию станции; запуск и остановка используют штатные скрипты проекта.

## Диагностика

- **Host key verification failed:** проверьте fingerprint и правильность записи `known_hosts`; не используйте `StrictHostKeyChecking=no`.
- **Permission denied:** проверьте пользователя, соответствующий приватный ключ и права доступа. Парольный вход модуль не поддерживает.
- **UID не 0:** выбранный аккаунт не имеет требуемых прав. Модуль не вызывает `su`, `sudo` или неизвестный механизм root.
- **Connection timed out / refused:** проверьте доступность станции, адрес, порт и уже настроенный SSH-сервер. MaxWave не меняет firewall и не включает SSH.
- **OpenSSH Client не найден:** установите системный компонент OpenSSH Client и убедитесь, что `ssh` доступен из терминала.

## Проверки и ограничения

Автоматические тесты в `tests/test_ssh.py` покрывают проверку параметров, защиту аргументов, строгую проверку host key, отключение парольной аутентификации, передачу команд через stdin и проверку UID 0. Успешное прохождение этих тестов не подтверждает совместимость с каждой реализацией SSH-сервера или прошивкой. Реальное подключение нужно отдельно проверить на конкретной станции.
